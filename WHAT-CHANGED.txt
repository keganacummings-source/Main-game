THE ROOT CAUSE OF MOST OF IT
----------------------------

Every test here loaded TypeScript by transpiling it to a `data:` URL. A data URL
has no directory, so the moment a source file contained `from "./something"`,
Node could not resolve it. The tests worked around that with a hand-written map
of specifier to URL — which meant adding one ordinary import to a source file
silently broke a test file that had never heard of it.

That is exactly what happened. `building.ts` grew an import of `./tile-atlas`,
and both survival-night and game-content started throwing — ASYNCHRONOUSLY,
after their own assertions had already passed. So the suite reported a file that
failed while every test inside it was green, and nobody could see what broke.

Worse, it was hiding tests. Converting those two files to a loader that resolves
relative imports itself revealed 43 tests that had not been running at all:

    game-content      5 tests visible  ->  41
    survival-night   10 tests visible  ->  17

One of those hidden tests immediately caught a real bug in my own Engineer
class (below).

  NEW   scripts/lib/ts-module.mjs — one loader, resolves relative imports
        recursively, handles .json, survives cycles, still supports a deliberate
        stub override for the few tests that genuinely want to fake a dependency.


REAL BUGS FIXED
---------------

1. tex-world.ts — the textured world's start point had no coordinates.

   `generateTexWorld` returned `spawn: {x, y}` where the map format is
   `{tx, ty}`. main-world.ts turns that into the player's start position, so a
   textured world was starting her at NaN, and map-format's own validation
   rejected the file outright. Two tests and one type error, all one bug.

2. tex-world.ts — unreachable pockets were "fixed" in a way that did nothing.

   There was already a pass meant to keep the world one piece: it turned
   unreachable land into a lake. But water is walkable (world.ts `blocked` lets
   you swim), so a sealed pocket just became a sealed pond and stayed exactly as
   cut off. It also never looked at water pockets at all, so small ponds ringed
   by rock survived untouched — and a fishing node rolled into one was a node no
   hunter could ever reach. Stranded ground is now made solid, which is what
   actually keeps the world connected.

3. tex-world.ts — dungeons showed old art in New Texture Mode.

   `retextureDungeon` replaced a tile's `layers` only when it was a portal, so
   every other decorated tile kept the generator's original art
   (/MapAssets/08_Statues_and_Landmarks/...). The mode promises it uses nothing
   but its own textures. Layers it does not own are now dropped; the layout
   (floor, block, portal) is untouched.

4. classes.ts — the Engineer had no class passive. MINE, from the class update.

   Every class has exactly one entry in CLASS_PASSIVES. I added the Engineer and
   never added hers, so she shipped with none. This is the bug the hidden tests
   caught the moment they started running. She now has "Powered Hands".

5. camp-assets.ts — two current machines could not be painted.

   POWER_TEXTURES listed 11 power blocks. The Ghost Merger and the GearSet Forge
   are current build pieces but were missing, so the Camp & Tile builder refused
   their textures and the shipped power pack silently lost them on import.

6. power-pack.json — retired content still shipping.

   The pack carried a BlockBreaker entry. The BlockBreaker was retired
   (power-extra.ts migrates old saves to the Rock Miner) and is not a build
   piece any more, so it was dead data that could never be imported. Removed.

7. enemy-design.ts — an unsound signature.

   `typedSpriteCanvas` declared `type: TypeId`, but it is called through a
   resolver with `String(m.type ?? "normal")` off live mob data, which can be
   anything. Widened to `string` with a guard that turns unknown types away.

8. map-format.ts — `seed` was written but not declared.

   tex-world has always recorded the seed it built from; the type never admitted
   it. Declared, so a generated world can be rebuilt exactly from its file.

9. scripts/power-extra.test.mjs and scripts/fight-depth.test.mjs were in NO npm
   script. Nobody ran them. power-extra had been failing silently — it could not
   even load (direct .ts imports, same extensionless-import problem). Both are
   fixed and both are now in `npm test`.


STALE TEST EXPECTATIONS CORRECTED
---------------------------------

I did not weaken anything to go green. Each of these asserted something the code
can no longer do, and I say what it checks now:

  - tex-world "zones.length > 80" could never pass: the generator lays 8 zones
    per region (3 per island) across 8-10 regions, then drops any near the edge,
    so the real count is 54-60 on every seed. It only ever "passed" because the
    reachability check above it failed first and the line never ran. Now checks
    the invariant behind it — every region is seeded, and all three gathering
    nodes exist.

  - power-extra looked for a single "power" build group. That group was split
    into power.gen / power.store / power.wiring / power.machines. Now checks the
    piece is in one of them.

  - power-extra expected an out-of-range machine facing to CLAMP (9 -> 3). The
    code WRAPS (9 % 4 = 1), deliberately, with the idiom that also brings a
    negative facing back into range. Corrected to the wrap, and I added the
    negative case it was missing.

  - power-extra's two BlockBreaker tests covered real behaviour — hauling into a
    chest, and a BlockGenerator refusing the wrong material — through a piece
    that no longer exists. Rewritten against the Rock Miner that replaced it.

  - game-content's moveset assertion is the V4 "exactly four" rule from the
    class update (already in your hands).


ABOUT THE TYPECHECK
-------------------

As I said last time, tsc here cannot check anything: node_modules holds only
TypeScript, so it aborts on two missing type libraries before reading a source
file. I keep a stub harness in scratch to get real checking. Against it, the
whole of src/ is now clean — the two pre-existing errors above (7 and 8) are
fixed, as are the two of my own from earlier drops.

Your `npm run typecheck` with real node_modules is still the only real gate.
