READ THIS FIRST — I owe you a correction
----------------------------------------

On the last two drops I told you "typecheck: 2 errors, same as baseline, no new
type errors". That was wrong, and I should have caught it sooner.

`node_modules` here contains nothing but TypeScript itself. Because `@types/node`
and `vite/client` cannot be resolved, tsc aborts on those two config errors
BEFORE it checks a single source file. I proved it this time by appending

    const CANARY: number = "definitely not a number";

to a component. tsc reported the same two errors and nothing else.

So "2 errors, same as baseline" never meant the code typechecked. It only meant
the same two config errors appeared. The class update and the UI overhaul were
delivered on that basis.

What I did about it: I built a stub harness in a scratch directory — minimal
declarations for react, react/jsx-runtime and lucide-react — which lets tsc get
past the missing libraries and actually check src/. It is loose about the
libraries and precise about hook signatures, so it has false positives (implicit
`any` on JSX event params, a missing `key` prop type) but it does catch real
mistakes.

Run against everything I have written this session, it found two genuine errors:

  1. hub-ui.tsx — `useMobileUi` used but never imported. A script of mine
     aborted halfway and I did not notice. This would have failed your build.
  2. game-panels.tsx — `verseHint(..., type: string)` passed to
     `typeClass(type: TypeId)`. From the UI overhaul, i.e. already in your
     hands in the last zip.

Both are fixed in this zip. After the fixes, zero genuine errors across src/.
The harness is NOT shipped — it is scratch only, and your own `npm run
typecheck` with real node_modules remains the real gate.


WHAT MOBILE MODE IS
-------------------

A toggle on the main menu — "Mobile mode", next to Options. Tap it and the whole
interface changes. Tap again for the full one.

It is a SETTING, not a media query, and that is deliberate: a phone-sized browser
window on a desktop is not a phone, a tablet with a keyboard often wants the full
interface, and a big touchscreen could want either. The one piece of automation is
the FIRST answer — with nothing stored, a device that cannot hover AND has a short
side under 820px starts in mobile mode. After that your choice wins forever, in
both directions. That is tested.


WHAT CHANGES WHEN IT IS ON
--------------------------

The desktop HUD is not restyled. It is not rendered at all. On a phone it would
be most of the screen covered by things you cannot press: a vitals panel, a foe
panel, a tracking column, an autoplay panel and an eleven-button dock.

In its place:

  TOP STRIP     who you are, health, mana and stamina, the foe when there is
                one, your effects and the last log line. Tap it for the
                character sheet.
  VERSE STRIP   your verses as a row you swipe along, with real cooldown faces
                and the Space item riding along at the end so it is never off
                the thumb's path.
  THUMB CLUSTER bottom-right: HIT, your R skill (with time-left and cooldown),
                and ☰.
  ☰ SHEET       every menu as a full-screen list of big targets.
  MOVE STICK    always on, bigger (116px), inside the safe area.

Nothing is lost. The desktop has a floating row of three toggles (HudFabs) that
mobile does not draw — Combat auto/manual, Autoplay and UNSTUCK. I nearly
shipped without them, which would have left a mobile player with no way out of a
bad spot. All three are in the ☰ sheet.

Panels become full-screen sheets. Dragging a title bar, resizing from a corner
and pinning are mouse ideas; on a phone they are three ways to lose a panel off
an edge. Every panel in the game is built on one component (float-win.tsx), so
one branch converts all of them: full screen, one close button, body scrolls.

Also, in mobile mode: hover cards are off entirely (a hint you cannot hover is a
card that appears when you try to tap something), keyboard badges are hidden,
buttons and inputs get a 42px minimum, and everything respects the safe-area
insets so nothing hides under a notch or a home bar.
